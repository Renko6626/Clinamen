# 多查询威胁读取与首轮实验

日期：2026-11-15。状态：用户已确认下列结构与本地实验准备范围，并要求开始实现。随后用户明确跳过短测并授权直接开始4000更新训练；实现与检查记录见[执行计划](../../experiments.md)。

## 问题与方案选择

在相同可见信息下，检验保留多个威胁摘要并继续交互，是否改善现代弹幕的组合避让。依据见[近期实验](../../experiments.md)与[研究待办](../../next-steps.md)。SA2和K128的负结果支持调整优先级，不能证明池化是唯一根因。

用户已认可多查询方向；具体替换范围由本方案提出：

| 方案 | 取舍 |
| --- | --- |
| **4查询替换弹／激光原汇总，再交流一层（推荐）** | 直接检验新的威胁读取结构，避免继续叠加旧分支；同时改变汇总方式、跨类型读取与摘要交互，首轮不能归因到某一组件 |
| 4查询与旧mean/max汇总并存 | 保留旧摘要，但分支更多，难判断新读取是否足以承担任务 |
| 4查询读取后直接拼接，不做摘要交互 | 实现更简单，关系组合仍全部留给MLP；适合作为有收益后的消融，不首轮同时铺开 |

## 推荐结构

使用现有danger_topk_v8、64弹＋8激光、d64／4头、1层联合自注意力。敌人编码、密度CNN、自机条件、256维两层主干和18动作／价值输出沿用现有口径。

```text
弹／激光各自MLP＋类型嵌入 → 72个token的单层联合自注意力 → H [B,72,64]
                                                                  ↓
自机与任务条件 → ctx [B,64] → 4个不同查询 → 交叉注意力读取 → Z [B,4,64]
                                                                  ↓
                                                   1层摘要间自注意力＋FFN
                                                                  ↓
                                                         展平为256维
                                                                  ↓
                                    拼接敌人摘要192维、密度64维、ctx64维
                                                                  ↓
                                              576→256→256主干 → actor／critic
```

- 查询初值为 `Q0[i] = W_ctx(ctx) + E[i]`；4个独立可学习的E，用随机小值打破对称，不预设方向、动作或职责。
- 一次Pre-LN交叉注意力：查询读取联合威胁token，采用4头、输出投影、查询残差及64→128→64的ReLU FFN；随后复用现有Pre-LN自注意力块，让4份摘要交流一次。
- 4份摘要按查询槽固定顺序展平，直接送入主干，不对它们再做mean/max。查询槽有各自身份；输入弹／激光的行顺序仍应不影响输出。
- **替换弹和激光两路的mean、max、单查询汇总**。这两类不再分别池化，而由同一组查询读取；类型嵌入继续区分它们。
- **敌人分支仍保留既有mean/max/单查询汇总**。本轮检验威胁读取，不同时重做敌人编码；这不是全模型去除mean/max。
- 掩码沿用现有约定，padding输入先清零；全无威胁时交叉注意力贡献为零，查询残差允许保留自机条件，输出必须有限且不依赖padding内容。不要求整个查询输出为零。
- 不保证查询自动分工；首轮不增加多样性损失、人工方向分区或额外reward。

## 实现范围与兼容性

建议新模型独立注册为 `set_attn_mq`，文件为 `src/stgtrain/models/set_attn_mq.py`；复用现有token编码与注意力块，不建立通用多后端框架。避免与本地已有、尚未采用的v4远场Perceiver原型混淆，不恢复该原型。

保留v3行为与旧checkpoint加载。新模型只构造实际使用的参数，不留下弹／激光旧池化的闲置参数。模型配置拟增加 `readout_queries=4`、`readout_sa_layers=1`；本轮action_query关闭，密度CNN开启。配置与注册只作必要接入。

外部特征字典和forward返回的logits／value形状保持不变；新模型从零训练，不设计旧权重迁移或放宽严格加载。ONNX沿用v8原始输入签名，内部架构改变本身不要求升级GRAPH_VERSION；准备阶段核对实际导出与自动对拍，不替换游戏部署模型。

工作区已有其他未提交改动；仅纳入本方案必要文件，不覆盖或清理原型、转写及其他实验修改。

## 首轮实验提案

先完成本地模型、配置与必要验证，随后申请单独GPU短测预算，以实测吞吐、显存和评测耗时确定正式训练预算。

| 项目 | 提议 |
| --- | --- |
| 参考基线 | 已完成的K64单层v3，从零u2000／u4000 checkpoint；不使用SA2或K128充当主对照 |
| 新实验 | MQ4，从零随机初始化，seed1；首轮只训这一条候选 |
| 训练模板 | 沿用exp-full-pretrain.toml；4096环境×64步、4epoch、num_minibatches=8（32768样本）、原LR与4000更新退火终点 |
| 训练长度 | 提议4000更新，共1,048,576,000环境帧；u2000作中期判断。若决定提前结束，记录实际终点，不临时改学习率退火终点 |
| 数据与任务 | 原686材料／668训练起点及排除项；Hard504／Normal14／Extra150，无Lunatic；reward、motor、课程、意图和训练时限沿用基线 |
| 存档与评测 | 每250更新存档，每500更新现代16卡1024局及原TH06留出832局；复用train_with_diagnostics.py，保持原训练留出划分 |
| 现代评测 | 固定seed12345，自由躲弹、warmup0、原motor、完整卡时限；Hard训练内表现与Lunatic升档泛化分别报告 |
| 主要观察 | 16卡Hard通过率、逐卡通过数与平均存活；重点查看TH15 s3_mb2／s4_b5、TH16里夏与冬终；Lunatic及TH06退化情况单列 |

现代诊断清单不得填入env.eval_splits，以免把这些训练内诊断卡移出训练。现有包装器按现代总体选择best，首轮沿用；架构结论比较固定u2000／u4000，不以各自best选择替代同量比较。

需要补齐的旧基线现代评测只跑缺失checkpoint／口径；最终用于比较的两模型在同一后端按同一协议评测。既有K64 u2000的1024局CPU结果可复用；u4000已有的局部TH16测试不能冒充完整16卡两档结果。

这是单seed、历史基线的结构筛选。更换读取还改变参数量、压缩维度和网络计算，不能把收益直接归为去掉mean/max；同seed也不保证两次训练共有参数初始化或采样轨迹相同。报告实际参数数、同训练帧数结果与墙钟成本。若需要改变minibatch才能运行，先提出比较方案，不能静默更改后声称纯结构对照。

首轮有清晰收益后，再决定是否做无摘要交互或加回mean/max的消融、重复seed；本轮不安排全组合扫描，也不预先规定小幅差异代表显著提升。
