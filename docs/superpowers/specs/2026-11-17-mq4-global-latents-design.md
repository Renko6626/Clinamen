# 下一阶段：以逐弹全局场景token替换CNN

日期：2026-11-17。

**状态：用户已认可下述方向和结构，要求先写文档，作为下一阶段工作。当前仅保存设计与研究入口，尚未实现、做性能短测或训练。** 输入512／1024的最终选择及运行预算待性能结果与用户决定；本文不构成启动收费实例、正式训练、部署、提交或推送的授权。已确认的结构无需下次重新讨论。

## 目标与依据

完整移除当前密度图和CNN通路，以较大范围的原始逐弹信息生成多个全局场景token，增强模型对弹墙、包围关系、远近通路和提前择路的表示能力。近场维持现有MQ4精细处理，把新增计算主要放在少量场景token上，避免数百颗弹逐层做两两自注意力。

用户明确希望卸掉CNN；保留或加大网格CNN不再是本阶段路线。性能成本是主要约束，不能因参数较少就假定训练便宜，也不能为增强可靠性扩展无关机制。

近期证据见[实验记录](../../experiments.md)和[共同弱项分析](../../practice-cards/2026-11-17-shared-weakness-analysis.md)：

- K128旧池化在同量u2000未胜过K64，SA2也未显示明确整体收益；这些结果不排除新的输入／读取组合。
- MQ4在同CPU、u4000现代16卡上从旧池化26.27%提高至33.79%，支持继续研究多个摘要及读取方式。
- 最新无位置任务MQ4在同GPU、u4000现代16卡为38.77%，原MQ4为34.57%；增益集中部分卡，密集弱项未普遍解决。以无位置任务配置作为下一阶段训练模板。
- 当前全局通路为两通道14×12密度图，经16通道小CNN投影为一个64维向量；格内位置、完整速度与半径信息未保留。新路线将精确原始量保留到可学习读取之前。

以上支持新假设，不证明CNN是失败主因。无位置任务基线为单训练seed，且u750曾迁移、重建环境与课程；后续比较保留这些限制。

## 路线选择

| 方案 | 取舍与本阶段决定 |
| --- | --- |
| 扩大现有MQ模型，或把CNN输出保留为网格token | 实现较直接，但仍受密度图格内信息丢失限制；用户本次明确选择移除CNN |
| 近场64维＋数百颗8／16维弹的完整自注意力 | 保留原始几何，但长序列两两注意力仍按输入数量平方增长；不作为首版 |
| 窄逐弹编码→少量较宽场景token→与近场摘要联合计算 | **选定路线**；输入读取对弹数线性增长，深层计算集中在短序列，代价是可学习摘要仍有压缩瓶颈及PPO缓存开销 |

参考[Perceiver](https://proceedings.mlr.press/v139/jaegle21a.html)与[Perceiver IO](https://arxiv.org/abs/2107.14795)的交叉读取思路；论文结果不作为本项目收益证据。

## 已选定结构

```text
近场64弹＋8激光
    ↓ 原64维、4头、一层联合注意力
    ↓ 原MQ4读取与一层摘要交流
4个近场token，每个64维 ───────────────────┐
                                         │
较大范围512／1024颗原始普通弹              │
    ↓ 相对位置2、绝对速度2、半径1          │
    ↓ 轻量MLP：5→16→16                    │
    ↓ 32个64维场景token交叉读取一次        │
32个全局token，每个64维 ──────────────────┤
                                         ↓
                           36个token联合Transformer两层
                                         ↓
                           全部展平＋原敌人汇总＋自机条件
                                         ↓
                           原256→256主干 → 18动作／价值
```

### 近场与其他信息

- 保留原MQ4的64颗近弹、8条激光、64维表示、4头、1层联合注意力、4查询及原1层摘要交流。近场弹的选择与归一化沿用当前行为。
- 使用无额外自机token的MQ4基线；保留原19维自机／条件和敌人汇总，不顺带重新设计这些输入。
- 激光仍由近场联合通路处理；新全局分支仅输入普通弹，不扩展激光数量或引擎观测接口。

### 全局读取

- 逐弹输入仍为原始5维：相对自机位置／192、绝对速度／8、半径／8，沿用当前尺度。保持mask，不加入预测安全方向、通道标签、碰撞时间等人为几何答案。
- 编码宽度先定16，MLP为5→16→16；首轮不另测8维，也不在长序列上增加自注意力。
- 32个可学习查询槽位，每个64维，由已有自机条件的投影调节。槽位含义由训练形成，不预先指定空间分区或强制分工。
- 一次交叉注意力读取全部入选弹。实现沿用现有Pre-LN、残差、FFN及SDPA习惯；64维注意力使用4头、FFN中间宽128。输入端16维会投影到注意力所需的key/value宽度，不能把全部中间激活按16维估算。
- 全局分支**包含近场弹**，不从候选中扣除Top-64。两路分别提供精细近场处理和整体关系，不要求互斥。
- 不按原始表行号添加位置编码；坐标是实际空间信息。无效槽不参与读取；全空输入须保持有限输出，不泄漏padding内容。

### 融合与输出

- 拼接4个近场token与32个全局token，做2层64维／4头联合自注意力，FFN宽128。
- 不再额外给全局32个token单独堆2层：本版新增的两层就是36个token的联合计算，避免把早期讨论中的两种安排叠加。
- 36×64全部展平，保留各槽位输出；不做末端mean/max或压回单个64维向量。与原敌人汇总192维、自机条件64维拼接，主干输入为2560维，后续256→256及actor／critic保持。
- 新模型完整移除CNN、密度投影及密度图计算／PPO缓存。旧模型与旧checkpoint路径保持可用，不直接把旧MQ4默认行为改掉。
- 约96万参数、约当前397203参数的2.4倍，仅为按上述模块形状推算，实施后核对真实参数数。参数量不等于训练耗时或显存倍数。

## 512与1024：待短测后选择

原CNN使用原始观测表中最多1024颗弹。新全局分支的两个候选为：

| 输入档 | 覆盖与用途 |
| --- | --- |
| 1024槽 | 读取当前原始表全部有效普通弹，与旧密度图的覆盖来源一致；**性能可接受时优先** |
| 512颗 | 读取当前原始表中距离自机最近的512颗有效普通弹；成本退让档，明确承认覆盖缩小 |

原始表上限仍为1024，不通过修改引擎cap实现512档。少于目标数时mask填充。512档具体距离排序须在实现前与当前近场／原始表口径核对并记录；训练与导出使用同一选择逻辑，不依赖部署原始表碰巧按某一顺序排列。即使导出入口接收更多原始槽位，也不能让部署侧悄悄获得比训练更大的观测范围。

这里“全局”只指当前观测表覆盖，不包含引擎截断的表外子弹。最近512颗不保证全屏分散覆盖；本轮不自动加入分区抽样、随机采样或其他空间采样机制。

## 性能与内存边界

交叉读取的主要注意力项随全局弹数N、场景槽数M、宽度d按N×M×d增长；本版M=32、d=64。后续联合自注意力只处理36个token。输入512→1024主要增加逐弹编码、key/value投影、交叉读取和缓存，联合两层的形状不变。

PPO需要保存原始特征，更新时重新经过可训练编码器；不缓存旧场景token来代替输入。按4096环境×64步、FP32逐弹特征、bool mask推算：

| 输入档 | 单份新增逐弹特征 | mask | 扣除原密度图后的单份净增加 |
| --- | ---: | ---: | ---: |
| 512 | 2.50 GiB | 0.125 GiB | 约2.30 GiB |
| 1024 | 5.00 GiB | 0.250 GiB | 约4.92 GiB |

原密度图缓存为2×14×12个FP32／样本，约0.328 GiB／rollout。上表不含反向激活、CUDA图私有池和缓存副本；当前PPO每epoch会整表打乱生成副本，实际显存峰值增量可能明显更高。删除CNN不保证新模型更快或更省显存。

讨论中提出过同机训练耗时尽量≤当前MQ4的1.5倍、超过2倍重新权衡；这是**待用户确认的性能目标**，不是已经测得的速度或已批准的费用上限。游戏侧CPU整图推理也需单独测量。

如果完整批量不适配，不静默减少minibatch、更改优化器更新次数、压缩观测精度或增加缓存搬运机制。这些改变须说明成本、训练口径及简单替代方案后再决定。

## 与旧原型的区别

[旧CNN消融结果](../../practice-cards/2026-10-10-density-p2-u2000-results.md)和[旧实现](../../../src/stgtrain/models/far_perceiver.py)仅供参考，不能直接恢复其任务、初始化或预算。

| 项目 | 旧原型 | 本阶段 |
| --- | --- | --- |
| 基础策略 | v3旧池化 | 无位置任务MQ4 |
| 输入 | 1024固定槽，mask排除近场64 | 512／1024候选，包含近场 |
| 逐弹编码 | 5→64→64 | 5→16→16 |
| 场景槽 | 8×64 | 32×64，自机条件查询 |
| 后续交流 | 一层场景自注意力 | 与4个近场摘要联合计算两层 |
| 输出 | 均值压成一个64维向量 | 36个token保留到主干 |
| 实验起点 | 旧权重适应路线 | 计划从零，以无位置任务MQ4为对照 |

旧原型未完成训练，不能称为已失败或已验证。历史上用户因逐弹缓存等成本暂停该路线；本次重新选择细粒度输入方向，并未消除缓存问题。旧CNN消融[P2结果](../../practice-cards/2026-10-10-density-p2-u2000-results.md)也不能证明新结构必然优于CNN。

## 下一阶段推进顺序

以下为后续工作顺序，本次只完成文档保存。

1. **本地实现与相关验证。** 沿用现有PyTorch、模型／特征化器注册方式和PPO数据流，不新增框架、引擎API或训练状态机。划清全局输入选择、模型编码融合、训练／导出接入的职责，先核对真实参数数、输入shape及CNN确实不再计算或缓存。复用现有模型夹具，覆盖padding、输入集合排列、空弹场景、真实前反向和权重保存加载；检查范围遵守项目约定，不扩成全项目测试工程。
2. **性能短测。** 在另行获准的设备／预算下，同机比较现MQ4和新结构512／1024两个输入档，测真实PPO吞吐与峰值显存，另测CPU推理。保留相同训练管线条件，短测只回答成本，不比较几十更新的能力，不默认训练两个正式模型。
3. **选择输入与正式预算。** 优先争取1024；成本不合适时提交512的实测与覆盖代价。训练量提议沿用从零4000更新，最终输入、批量及费用上限在运行前确定。
4. **正式能力比较。** 使用[无位置任务配置](../../../configs/exp-full-pretrain-mq4-free.toml)作模板，保留操作平滑、贴边惩罚、运动闸、PPO、课程、判定增大和原卡池／排除项。沿用现代16卡同口径评测，Hard训练内和Lunatic升档分开；重点报告里夏、冬终、TH15密集直线与TH18延迟加速弱项，不能只看总体均值。TH06使用一致的自由躲弹口径，不能与旧跟点评测直接相减。先不扩展全639卡、多个seed或全组合消融。

训练与部署必须复用同一特征化选择和尺度；按项目要求检查ONNX对拍与图签名，只有真实签名改变时同步两侧GRAPH_VERSION。涉及PPO、CUDA图或torch／tensordict API改动，遵守项目旧版本兼容检查要求；CPU检查不替代GPU验证。正式实验权重不自动替换部署模型。

## 能回答的问题与暂缓事项

本轮检验“逐弹全局输入＋多个场景token＋近远联合计算”整体方案是否值得其成本，不能单独归因于移除CNN、增加槽位或增加深度。32个token仍是压缩瓶颈，softmax读取不保证保留全部细缝或绝对弹数；不预设其自动形成稳定空间分工。

本版没有跨帧记忆，也不能凭当前状态准确预知无前兆的脚本变化。暂不同时加入时序网络、额外预测／辅助损失、slot分工约束、弹数新特征、复杂空间采样或更改reward／运动闸。确有实验依据后再单独讨论。

未决项集中为：512／1024最终输入档、实际性能与显存、运行费用和训练预算。当前选定架构不因这些运行参数待定而退回“下一轮方向尚未选择”。
